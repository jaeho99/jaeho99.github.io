# 개발의 해상도 정보구조

## 방문자 진입 경로

```text
홈
├─ 전체 글
│  ├─ 주제 바로가기
│  └─ 최신순 글 목록
├─ 주제
│  ├─ Backend
│  │  ├─ Java
│  │  ├─ Spring
│  │  └─ Python · Database · API
│  ├─ Frontend
│  │  ├─ JavaScript · React · Vue
│  │  └─ Nexacro · WebSquare
│  ├─ DevOps
│  │  └─ CI/CD · Docker · Cloud · Infrastructure
│  ├─ Tooling
│  ├─ CS Fundamentals
│  ├─ Algorithms
│  └─ Projects
├─ 로드맵
└─ 소개
```

각 게시글은 `홈 → 주제 → 대분류 → 중분류 → 게시글` 경로에 속한다. 대분류는 개발 영역, 중분류는 기술이나 문제 유형, 태그는 글 안의 세부 키워드를 나타낸다.

## 페이지별 역할

- 홈: 블로그의 관점, 주제 허브, 최근 글과 작성 원칙을 소개한다.
- 전체 글: 모든 글을 최신순으로 탐색한다.
- 주제: 관심 분야를 선택하는 최상위 탐색 허브다.
- 대분류: 같은 개발 영역의 중분류와 전체 글을 함께 보여준다.
- 중분류: 특정 기술이나 문제 유형의 글만 모아 보여준다.
- 게시글: 브레드크럼, 읽기 시간, 목차와 이전·다음 글로 긴 읽기를 지원한다.
- 로드맵: 예정된 주제와 작성 방식을 공개한다.
- 소개: 작성자와 기록 원칙, 외부 채널을 설명한다.

## 콘텐츠 분류 원칙

1. 모든 글에는 대분류 `category`와 중분류 `subcategory`를 각각 하나만 지정한다.
2. 글을 가로지르는 기술명과 세부 키워드는 여러 `tags`로 지정한다.
3. 등록된 분류 중 게시글이 없는 항목은 공개 탐색 화면에서 숨긴다.
4. 탐색 깊이는 중분류까지로 제한하고, 연속 글은 별도의 시리즈 기능으로 분리한다.
5. 기존 URL은 리다이렉트해 방문자와 검색엔진의 경로를 보존한다.

## 퍼블리싱 원칙

- 모바일에서 제목, 태그, 표와 코드가 본문 폭을 밀어내지 않아야 한다.
- 모든 페이지에서 키보드 포커스가 보여야 한다.
- 긴 게시글은 데스크톱 고정 목차와 모바일 접이식 목차를 제공한다.
- 현재 위치는 브레드크럼과 주 메뉴 활성 상태로 표시한다.
- 주제 카드, 글 카드와 이전·다음 글의 링크 영역은 충분한 클릭 면적을 제공한다.
