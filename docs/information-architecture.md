# 개발의 해상도 정보구조

## 방문자 진입 경로

```text
홈
├─ 전체 글
│  ├─ 주제 바로가기
│  └─ 최신순 글 목록
├─ 주제
│  ├─ Java · Spring
│  ├─ JavaScript · Frontend
│  ├─ DevOps · Infrastructure
│  └─ Project · Retrospective
├─ 로드맵
└─ 소개
```

각 게시글은 `홈 → 주제 → 대표 카테고리 → 게시글` 경로에 속한다. 카테고리는 글의 대표 맥락 하나를 나타내고 태그는 세부 기술을 나타낸다.

## 페이지별 역할

- 홈: 블로그의 관점, 주제 허브, 최근 글과 작성 원칙을 소개한다.
- 전체 글: 모든 글을 최신순으로 탐색한다.
- 주제: 관심 분야를 선택하는 최상위 탐색 허브다.
- 카테고리: 같은 맥락의 글을 모아 보여주고 다른 주제로 이동시킨다.
- 게시글: 브레드크럼, 읽기 시간, 목차와 이전·다음 글로 긴 읽기를 지원한다.
- 로드맵: 예정된 주제와 작성 방식을 공개한다.
- 소개: 작성자와 기록 원칙, 외부 채널을 설명한다.

## 콘텐츠 분류 원칙

1. 모든 글에는 대표 `category`를 하나만 지정한다.
2. 기술명, 도구명과 세부 주제는 여러 `tags`로 지정한다.
3. 카테고리는 최소 3편 이상의 글을 묶을 수 있을 때 추가한다.
4. 특정 기술의 연속 글이 충분히 쌓이면 카테고리가 아니라 시리즈 기능으로 분리한다.
5. 기존 URL은 특별한 이유가 없으면 변경하지 않는다.

## 퍼블리싱 원칙

- 모바일에서 제목, 태그, 표와 코드가 본문 폭을 밀어내지 않아야 한다.
- 모든 페이지에서 키보드 포커스가 보여야 한다.
- 긴 게시글은 데스크톱 고정 목차와 모바일 접이식 목차를 제공한다.
- 현재 위치는 브레드크럼과 주 메뉴 활성 상태로 표시한다.
- 주제 카드, 글 카드와 이전·다음 글의 링크 영역은 충분한 클릭 면적을 제공한다.
