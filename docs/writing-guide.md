# 백엔드 개발 기록 작성 가이드

## 채널 역할

- Astro 블로그: 검색과 포트폴리오에 사용할 공식 원문
- GitHub: 원문, 재현 코드, 테스트와 수정 이력
- Velog: 핵심 요약과 공식 원문으로 연결하는 글

같은 전문을 여러 플랫폼에 복제하지 않는다. 공식 원문 URL은 Astro 블로그로 통일한다.

## 글의 기본 구조

1. 실행 환경과 검증 상태
2. 문제 상황과 관찰한 증상
3. 최소 재현 방법
4. 원인 분석
5. 해결 방법과 대안 비교
6. 검증 결과와 남은 한계
7. 재현 코드 및 공식 참고 자료

## 공개 전 확인

- 회사 소스, 내부 URL, 고객 데이터, 계정과 비밀 값이 없는가
- 독립 예제로 같은 현상을 설명할 수 있는가
- 실행한 테스트와 실행하지 못한 검증을 구분했는가
- 버전, 날짜, 코드 경로와 원문 URL이 맞는가
