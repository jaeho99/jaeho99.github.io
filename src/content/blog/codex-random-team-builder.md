볼링 모임에서 즉석으로 팀을 나눌 때 필요한 것은 복잡한 회원 시스템이 아니다. 참가자를 입력하고 팀을 확인한 뒤 모든 데이터가 사라지면 된다.

처음 요구사항은 명확했다.

- 설치 과정이 없어야 한다.
- 컴퓨터 메모리를 적게 사용해야 한다.
- 결과 확인 후 참가자 데이터가 남지 않아야 한다.
- 꼭 Java일 필요는 없다.

이 조건에서는 서버 애플리케이션보다 브라우저에서 바로 실행되는 단일 HTML이 적합했다. Codex와 함께 `index.html` 하나로 동작하는 랜덤 팀 배정 프로그램을 만들었다.

## 기술을 덜 쓰는 것이 설계였다

프로젝트에는 서버, 데이터베이스와 빌드 도구가 없다. HTML 파일을 더블클릭하면 실행된다.

```text
index.html
├─ 화면 구조와 스타일
├─ 참가자 입력
├─ 팀 배정 알고리즘
└─ 카드 뽑기 상호작용
```

참가자와 결과는 JavaScript 메모리에만 존재한다. `localStorage`, 쿠키, 서버 전송을 사용하지 않으므로 새로고침하거나 탭을 닫으면 데이터가 사라진다.

이 프로젝트에서 “저장하지 않음”은 빠진 기능이 아니라 개인정보를 남기지 않기 위한 요구사항이다.

## 균등한 팀을 만드는 방법

참가자 순서를 무작위로 섞은 뒤 팀에 순서대로 배치한다. 셔플에는 Web Crypto API로 생성한 난수를 사용하는 Fisher–Yates 알고리즘을 적용했다.

```text
원본: A B C D E F G
셔플: D A G C F B E
배정: 1팀(D, C, E), 2팀(A, F), 3팀(G, B)
```

사용자는 팀 개수 또는 팀당 최대 인원을 기준으로 배정할 수 있다. 나머지 인원을 앞쪽 팀부터 한 명씩 나누면 팀 간 인원 차이가 최대 한 명으로 유지된다.

## 결과보다 과정이 재미있어야 했다

처음에는 버튼을 누르면 팀 명단이 즉시 표시되는 기능만 있었다. 실제 모임에서는 참가자들이 직접 카드를 선택하는 편이 더 재미있다는 요구가 추가됐다.

카드 뽑기 모드는 다음 방식으로 동작한다.

1. 팀 인원에 맞춰 색상 카드 묶음을 만든다.
2. 카드 순서를 무작위로 섞는다.
3. 참가자가 한 명씩 뒤집는다.
4. 같은 색을 선택한 참가자가 같은 팀이 된다.
5. 마지막에 팀별 명단을 공개한다.

이름을 미리 입력하지 않아도 참가자 수만으로 진행할 수 있다. 이 경우 `참가자 1`, `참가자 2`처럼 선택 순서를 표시한다.

## 대형 모니터라는 사용 환경

모바일 반응형 화면을 만들던 초기 방향은 실제 환경과 맞지 않았다. 이 프로그램은 볼링장 모니터에 띄우고 여러 사람이 멀리서 보는 도구였다.

따라서 UX 기준을 다음처럼 바꿨다.

- 카드 뽑기 시작 시 설정 화면 숨김
- 카드 영역이 화면 전체를 사용
- 카드 수에 따라 크기와 배열 자동 조정
- 동물 그림 또는 숫자로 카드를 말로 지목
- 25명이 넘으면 동물과 작은 순번을 조합
- `Esc`로 설정 화면 복귀
- 최종 팀 명단의 글자를 크게 표시

“몇 번째 카드를 고르세요”보다 “호랑이 카드”, “7번 카드”처럼 말할 수 있게 만든 것이 현장 사용성을 크게 높였다.

## Codex 협업에서 배운 점

이 프로젝트는 기술 선택이 목적과 비례해야 한다는 좋은 사례였다. Spring Boot나 React를 사용할 수도 있었지만, 단일 HTML이 요구사항을 더 잘 만족했다.

Codex와 작업하면서도 구현 전에 다음 질문을 반복했다.

- 실제로 어디에서 사용하는가?
- 사용 후 데이터를 보존해야 하는가?
- 참가자가 화면을 얼마나 멀리서 보는가?
- 결과를 얻는 속도와 참여의 재미 중 무엇이 중요한가?

도구가 간단할수록 이런 질문의 답이 코드 구조에 직접 반영된다.

## 다음 개선점

- 셔플과 균등 배정 알고리즘에 자동 테스트 추가
- 전체 화면 API를 이용한 브라우저 UI 숨김
- 팀별 색상이 색각 이상 사용자에게도 구분되는지 검증
- 결과를 이미지로 저장하는 선택 기능

작은 프로그램이지만 과도한 기술 없이 요구사항에 맞는 구조를 선택하고, 실제 장소에 맞춰 UX를 바꾼 경험을 담고 있다.
