볼링장에서 캡슐 경기를 진행하면 첫 게임이 끝난 뒤 이런 계산이 필요하다.

- 현재 팀 점수는 몇 점인가?
- 목표까지 몇 점이 남았는가?
- 두 번째 게임에서 남은 선수들은 각각 몇 점을 쳐야 하는가?
- 여자 선수 핸디를 적용하면 목표점수는 얼마인가?

계산 자체는 복잡하지 않지만 경기 도중 휴대폰 계산기로 여러 번 계산하기는 번거롭다. 그래서 Codex와 함께 **서버 없이 작동하는 캡슐 점수 계산기**를 만들었다.

## 요구사항을 계산 규칙으로 바꾸기

팀 목표점수는 경기 요일과 인원에 따라 달라진다.

| 구분 | 2인조 | 3인조 | 4인조 | 5인조 |
|---|---:|---:|---:|---:|
| 월·화·수 | 700 | 1,030 | 1,340 | 1,650 |
| 나머지 요일 | 720 | 1,050 | 1,360 | 1,680 |

여자 선수에게는 한 게임당 15점의 핸디가 있으므로 2게임 합산 목표에서는 1명당 30점을 차감한다.

```text
조정 목표점수 = 인원·요일별 기본 목표점수 - 여자 선수 수 × 30
```

처음에는 첫 게임 점수만 입력하고 두 번째 게임의 팀 목표를 보여주는 형태였다. 실제 사용 상황을 생각해보니 두 번째 게임도 선수별로 종료 시점이 달랐다. 5명 중 3명이 경기를 마쳤다면 남은 2명이 몇 점을 기록해야 하는지 즉시 보여줘야 했다.

## 남은 점수를 정수로 배분하기

현재 합계와 남은 목표를 계산한 뒤, 아직 두 번째 게임 점수가 입력되지 않은 사람에게 점수를 나눈다.

```ts
const remainingNeeded = Math.max(target - currentTotal, 0);
const perRemaining = remainingPlayers > 0
  ? remainingNeeded / remainingPlayers
  : 0;

const low = Math.floor(perRemaining);
const highCount = remainingNeeded - low * remainingPlayers;
const lowCount = remainingPlayers - highCount;
```

평균만 `187.5점`처럼 보여주면 실제 경기에서는 다시 계산해야 한다. 그래서 `188점 1명 + 187점 1명`처럼 정수 점수 배분도 함께 표시했다.

한 선수의 필요 점수가 300점을 넘으면 현실적으로 달성할 수 없다는 안내를 보여준다. 반대로 이미 목표를 달성했다면 남은 선수의 점수와 관계없이 달성 상태로 전환한다.

## 날짜가 아니라 경기일을 계산하기

볼링 경기는 자정을 넘겨 끝날 수 있다. 단순히 현재 날짜의 요일을 쓰면 화요일 새벽 1시 경기를 화요일 경기로 잘못 계산한다.

이를 해결하기 위해 한국 시간 기준 새벽 3시를 하루의 경계로 정했다.

```ts
const gameDate = new Date(Date.now() - 3 * 60 * 60 * 1000);
```

현재 시각에서 3시간을 뺀 날짜의 요일을 사용하면 화요일 새벽 2시는 월요일 경기로, 새벽 3시 이후는 화요일 경기로 처리할 수 있다.

## 왜 서버와 데이터베이스를 쓰지 않았나

이 도구의 목적은 점수를 저장하거나 여러 사용자와 공유하는 것이 아니다. 경기장에서 한 번 계산하고 닫으면 끝난다. 따라서 서버와 DB를 추가하면 운영 비용과 장애 지점만 늘어난다.

모든 계산은 React 상태와 브라우저에서 수행한다. Service Worker를 등록해 한 번 방문한 뒤에는 인터넷 연결이 불안정해도 사용할 수 있도록 PWA 형태로 구성했다.

## Codex와 반복 개선한 방식

한 번에 완성된 요구사항을 전달한 것이 아니라 실제 사용 장면을 떠올리며 단계적으로 수정했다.

1. 인원과 여자 선수 수에 따른 목표점수 계산
2. 첫 게임 선수별 점수 입력
3. 두 번째 게임 진행 중 점수 입력
4. 남은 선수별 필요 점수 배분
5. 한국 시간 새벽 3시 기준 요일 자동 적용
6. 인당 2게임 목표와 1게임 평균 표시
7. PWA·오프라인 지원과 공개 배포

Codex는 구현과 검증 속도를 높였고, 나는 경기 규칙과 실제 사용 상황을 계속 구체화했다. AI 협업에서 중요한 것은 처음부터 긴 명세를 완벽하게 만드는 것보다 **작동하는 결과를 직접 써보고 다음 요구사항을 정확하게 전달하는 과정**이었다.

## 다음 개선점

- 목표점수 설정을 사용자 정의로 확장
- 실제 경기장에서 사용성 테스트 후 글자 크기와 입력 동선 조정
